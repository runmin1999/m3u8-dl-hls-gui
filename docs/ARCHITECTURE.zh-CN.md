## 1. M3U8 解析

### 1.1 什么是 M3U8

M3U8 是 HLS（HTTP Live Streaming）协议使用的播放列表格式。它是一个纯文本文件，描述了视频的分片信息。HLS 将视频切成 small 的 `.ts` 片段，通过 HTTP 逐个下载。

### 1.2 两种 Playlist 类型

```
┌─────────────────────────────────────────────────────────┐
│                   Master Playlist                        │
│  (多码率入口，指向多个 Media Playlist)                    │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  #EXT-X-STREAM-INF:BANDWIDTH=800000,RESOLUTION=640x360 │──→ 360p.m3u8
│  #EXT-X-STREAM-INF:BANDWIDTH=2000000,RESOLUTION=1280x720│──→ 720p.m3u8
│  #EXT-X-STREAM-INF:BANDWIDTH=5000000,RESOLUTION=1920x1080│──→ 1080p.m3u8
│                                                         │
└─────────────────────────────────────────────────────────┘
                         │
                         ▼ 用户选择码率
┌─────────────────────────────────────────────────────────┐
│                   Media Playlist                         │
│  (实际的 TS 分片列表)                                     │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  #EXT-X-TARGETDURATION:10                                │
│  #EXT-X-KEY:METHOD=AES-128,URI="key.bin"               │
│  #EXTINF:9.009,                                         │
│  segment000.ts                                          │
│  #EXTINF:9.009,                                         │
│  segment001.ts                                          │
│  #EXTINF:5.005,                                         │
│  segment002.ts                                          │
│  ...                                                    │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 1.3 解析流程

```
M3U8 文本内容
    │
    ▼
┌──────────────────┐
│  检查 #EXTM3U 头  │ ← 无效文件则报错
└────────┬─────────┘
         │
         ▼
┌──────────────────────────────┐
│ 检测是否包含 #EXT-X-STREAM-INF │
└────────┬─────────────────────┘
         │
    ┌────┴────┐
    │         │
    ▼         ▼
  Master   Media
  Playlist Playlist
    │         │
    ▼         ▼
  解析码率流  解析分片列表
  ┌────────┐ ┌────────────────┐
  │BANDWIDTH│ │EXTINF: 时长     │
  │RESOLUTION│ │EXT-X-KEY: 加密  │
  │URL: 地址 │ │分片URL          │
  └────────┘ └────────────────┘
```

### 1.4 关键解析逻辑

**属性解析正则**：`([A-Z0-9_-]+)=("([^"]*)"|([^,]*))`

- 匹配 `KEY=VALUE` 或 `KEY="VALUE"` 格式
- 支持带引号的值（如 `CODECS="avc1.64001e,mp4a.40.2"`）

**相对 URL 拼接**：使用 `urllib.parse.urljoin` 将相对路径转为绝对路径

**加密信息传递**：`EXT-X-KEY` 会向下传递给后续分片，直到遇到新的 `EXT-X-KEY` 标签

## 2. 多线程下载（M3U8）

### 2.1 架构设计

```
┌─────────────────────────────────────────────────────┐
│                  ThreadPoolExecutor                  │
│                  (默认 20 并发)                       │
├─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────────┤
│ T1  │ T2  │ T3  │ T4  │ T5  │ T6  │ ... │  T20    │
└──┬──┘└──┬─┘└──┬──┘└──┬──┘└──┬──┘└──┬──┘└──┬──┘└───┬──┘
   │      │     │      │      │      │      │       │
   ▼      ▼     ▼      ▼      ▼      ▼      ▼       ▼
┌─────────────────────────────────────────────────────┐
│              requests.Session (连接池)               │
│         HTTPAdapter(pool_connections=50,             │
│                     pool_maxsize=50)                 │
├─────────────────────────────────────────────────────┤
│  连接1    连接2    连接3    连接4   ...   连接50      │
└─────────────────────────────────────────────────────┘
   │        │        │        │              │
   ▼        ▼        ▼        ▼              ▼
 HTTP服务器（TS 分片文件）
```

### 2.2 原子写入机制

```
写入流程：

  session.get(segment.url)
       │
       ▼
  ┌──────────────┐
  │ 写入 .tmp 文件 │  ← 临时文件，写入过程中如果中断不会影响目标文件
  │ (流式写入)    │     chunk_size=8192 (8KB)
  └──────┬───────┘
         │ 写入完成
         ▼
  ┌──────────────┐
  │ os.replace   │  ← 原子操作：瞬间替换
  │ .tmp → .ts   │     要么完整存在，要么不存在
  └──────────────┘
```

### 2.3 重试策略

```
下载失败
   │
   ▼ 第 1 次重试（等待 1 秒）
   │── 成功 → 返回
   │── 失败 ↓
   ▼ 第 2 次重试（等待 2 秒）
   │── 成功 → 返回
   │── 失败 ↓
   ▼ 第 3 次重试（等待 3 秒）
   │── 成功 → 返回
   │── 失败 ↓
   ▼ 第 4 次重试（等待 4 秒）
   │── 成功 → 返回
   │── 失败 ↓
   ▼ 第 5 次重试（等待 5 秒）
   │── 成功 → 返回
   │── 失败 → 标记为失败分片
```

### 2.4 线程安全

```python
# 共享变量通过 threading.Lock 保护
_lock = threading.Lock()

with _lock:
    results[seg.index] = filepath   # 更新结果
    completed += 1                   # 更新计数
    bytes_downloaded += seg_size     # 更新字节数
```

## 3. MP4 直链下载

### 3.1 概述

MP4 直链下载使用 `curl.exe --parallel` 进行高性能多连接下载，支持自动重试和断点续传。

### 3.2 架构设计

```
┌─────────────────────────────────────────────────────────┐
│                    MP4 下载（curl.exe）                    │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  curl.exe --parallel --parallel-max N                   │
│                                                         │
│  ┌─────────┬─────────┬─────────┬─────────┐             │
│  │连接 1   │连接 2   │连接 3   │连接 N   │             │
│  └────┬────┘└────┬───┘└────┬───┘└────┬───┘             │
│       │          │         │         │                  │
│       ▼          ▼         ▼         ▼                  │
│  ┌─────────────────────────────────────────┐            │
│  │         单个输出文件（.tmp）              │            │
│  │         curl 直接写入                    │            │
│  └─────────────────────────────────────────┘            │
│                                                         │
│  Python 监控：                                           │
│  - 文件大小 → 进度和速度                                  │
│  - 进程存活 → 完成检测                                    │
│  - 停止/暂停标志 → 终止并续传                             │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 3.3 自动重试续传

```
下载进行中
    │
    ▼ curl 退出（网络错误、超时等）
    │
    ▼ 检查最终文件大小
    │
    ├── 完成 → 重命名 .tmp → .mp4，完成 ✓
    │
    ├── 不完整 → retry_count++
    │   │
    │   ├── retry_count < 10 → 等待 2 秒，用 -C - 重启（续传）
    │   │
    │   └── retry_count >= 10 → 标记为失败
    │
    └── 无文件 → retry_count++，重启
```

### 3.4 暂停/恢复机制

```
用户点击"暂停"
    │
    ▼
┌──────────────────┐
│ task._pause_flag  │
│ = True            │
└──────────────────┘
        │
        ▼ 监控循环检测到暂停
┌──────────────────┐
│ proc.kill()      │ ← 终止 curl 进程
│                  │
│ while _pause_flag│
│   sleep(0.3)     │ ← 等待恢复
└──────────────────┘
        │
        ▼ 用户点击"继续"
┌──────────────────┐
│ _pause_flag =    │
│   False           │
│ 重启 curl        │
│ 使用 -C -        │ ← 从上次位置续传
└──────────────────┘
```

### 3.5 配置参数

`config.json` 中的隐藏配置项：

```json
{
  "parallel_max": 8,         // curl 并行连接数（1-32）
  "ffmpeg_concurrency": 2    // FFmpeg 并发合并进程数（1-16）
}
```

## 4. AES-128 解密

### 4.1 加密原理

HLS 使用 AES-128-CBC 模式加密 TS 分片：

```
明文数据（TS 分片）
      │
      ▼
┌─────────────────────────────────┐
│         AES-128-CBC 加密         │
│                                 │
│  密钥（16字节）──→ AES 加密器     │
│  IV（16字节）───→              │
│  明文数据 ─────→              │
│                   ↓            │
│              密文数据            │
└─────────────────────────────────┘
```

### 4.2 解密流程

```
M3U8 中的 EXT-X-KEY 标签
│
├── METHOD=AES-128
├── URI="https://example.com/key.bin"   ← 密钥地址
└── IV=0x1234567890ABCDEF...            ← 初始化向量（可选）
         │
         ▼
┌──────────────────────────────┐
│   fetch_key(key_url)         │
│                              │
│   查密钥缓存 ──命中──→ 返回缓存密钥
│       │                      │
│       未命中                  │
│       ▼                      │
│   HTTP GET key.bin           │
│       │                      │
│       ▼                      │
│   返回 16 字节密钥            │
│   写入缓存（线程安全）         │
└──────────────────────────────┘
         │
         ▼
┌──────────────────────────────┐
│   decrypt_segment()          │
│                              │
│   encrypted_data（密文）       │
│   key（16字节密钥）            │
│   iv（16字节 IV）             │
│       │                      │
│       ▼                      │
│   AES.new(key, CBC, iv)     │
│       │                      │
│       ▼                      │
│   AES.decrypt(data)          │
│       │                      │
│       ▼                      │
│   去除 PKCS7 填充             │
│       │                      │
│       ▼                      │
│   返回明文数据                │
└──────────────────────────────┘
```

### 4.3 PKCS7 填充

AES 要求数据长度为 16 的倍数，PKCS7 在末尾填充：

```
原始数据（14字节）:  [A][B][C][D][E][F][G][H][I][J][K][L][M][N]
PKCS7 填充 2 字节:  [A][B][C][D][E][F][G][H][I][J][K][L][M][N][02][02]
                                                               ↑填充

原始数据（16字节）:  [A][B][C][D][E][F][G][H][I][J][K][L][M][N][O][P]
PKCS7 填充 16 字节: [A][B][C][D][E][F][G][H][I][J][K][L][M][N][O][P][10]...[10]
```

### 4.4 密钥缓存

```
第 1 个加密分片
    │
    ▼
key_url 在缓存中？
    │── 是 → 直接返回缓存密钥
    │── 否 ↓
    │
    HTTP GET key_url
    │
    ▼
    保存到 _key_cache[key_url] = key
    │
    ▼
    返回密钥

第 N 个加密分片（使用相同 key_url）
    │
    ▼
key_url 在缓存中？ → 命中 → 直接返回（跳过网络请求）
```

## 5. 断点续传

### 5.1 原理

断点续传基于两个关键设计：

1. **原子写入**：每个分片文件写入 `.tmp` 后再重命名，确保已下载的 `.ts` 文件是完整的
2. **索引集合**：记录已成功下载的分片索引

### 5.2 流程

```
任务启动 / 恢复
    │
    ▼
┌──────────────────────────────┐
│  加载已下载分片索引集合        │
│  _downloaded_indices = {0,1,2}│
└──────────────┬───────────────┘
               │
               ▼
┌──────────────────────────────┐
│  遍历所有分片                 │
│                              │
│  for seg in segments:        │
│    if seg.index in indices:  │
│      验证 .ts 文件存在且 > 0  │
│      │── 存在 → 跳过（不下载）│
│      │── 不存在 → 重新下载    │
│    else:                     │
│      加入下载队列             │
└──────────────┬───────────────┘
               │
               ▼
┌──────────────────────────────┐
│  多线程下载未完成的分片        │
│  下载成功后更新索引集合        │
└──────────────┬───────────────┘
               │
               ▼
┌──────────────────────────────┐
│  保存索引集合到 tasks_history  │
│  下次启动时可恢复             │
└──────────────────────────────┘
```

### 5.3 暂停/恢复机制

```
用户点击"暂停"
    │
    ▼
┌──────────────────┐
│ task._pause_flag  │
│ = True            │
│ task.status =     │
│   "paused"        │
└──────────────────┘
        │
        ▼  下载线程中的 stop_check() 检测到暂停
┌──────────────────┐
│ while _pause_flag │
│   sleep(0.3)     │  ← 循环等待，不退出线程
│                  │
│   _stop_flag?    │── True → 退出（用户点了停止）
│     │            │
│     False        │
│     ↓            │
│   继续等待       │
└──────────────────┘
        │
        ▼ 用户点击"继续"
┌──────────────────┐
│ _pause_flag =    │
│   False           │
│ _stop_flag =     │
│   False           │
│ status =         │
│   "downloading"  │
└──────────────────┘
        │
        ▼  stop_check() 返回 False，下载线程恢复执行
```

## 6. 分辨率选择

### 6.1 流程

```
用户输入 M3U8 URL
    │
    ▼
解析 Master Playlist
    │
    ▼

    │
    ▼

```

## 7. 代理支持

### 7.1 配置方式

```
用户在 GUI 输入代理地址
    │
    ▼
┌──────────────────────────┐
│ 代理地址:                 │
│ http://127.0.0.1:7890    │
│ socks5://127.0.0.1:1080  │
└──────────────────────────┘
    │
    ▼ 自动保存到 config.json
```

### 7.2 代理应用位置

代理配置会传递到所有网络请求：

```
proxy = "http://127.0.0.1:7890"
    │
    ├──→ fetch_m3u8()         获取 M3U8 文件
    ├──→ download_segment()   下载 TS 分片
    ├──→ fetch_key()          获取 AES 密钥
    └──→ 合并/解密            本地操作，不经过网络

每个 requests 请求都配置：
proxies = {
    "http": proxy,
    "https": proxy
}
```

### 7.3 请求链路

```
应用 → HTTP 代理服务器 → 目标服务器
  │         │                │
  │    代理转发请求       代理转发响应
  │         │                │
  ◄─────────◄────────────────◄
```

## 8. 自定义请求头

### 8.1 Referer 防盗链

很多视频服务器通过检查 Referer 头来判断请求来源，防止盗链：

```
服务器检查：
┌──────────────────────────────────────┐
│  Referer: https://example.com/video  │
│           ↑                          │
│  必须匹配预期的域名，否则返回 403       │
└──────────────────────────────────────┘

应用配置：
┌──────────────────┐
│ Referer 来源页:   │
│ https://example.com/video │ ← 用户填写
└──────────────────┘
    │
    ▼
所有 HTTP 请求自动携带：
headers = {
    "Referer": "https://example.com/video",
    "User-Agent": "Mozilla/5.0 ..."
}
```

### 8.2 应用位置

```
用户填写 Referer
    │
    ▼
自动保存到 config.json
    │
    ▼
创建任务时写入 task.custom_headers
    │
    ├──→ fetch_m3u8()      请求 M3U8 时携带
    ├──→ download_all()    下载分片时携带
    └──→ fetch_key()       获取密钥时携带
```

## 9. 本地 M3U8 支持

### 9.1 概述

用户可以通过 Ctrl+V 粘贴本地 `.m3u8` 文件路径。应用直接读取文件内容，解析分片 URL，然后从远程服务器下载分片。

### 9.2 流程

```
用户粘贴本地路径（如 D:\Videos\index.m3u8）
    │
    ▼
┌──────────────────────┐
│ 检测到 Ctrl+V        │
│ os.path.isfile() ✓   │
└──────┬───────────────┘
       │
       ▼
┌──────────────────────┐
│ 读取文件内容          │
│ 存储到               │
│ _local_m3u8_content  │
│ URL 设为文件路径      │
└──────┬───────────────┘
       │
       ▼
┌──────────────────────┐
│ parse_and_create()   │
│ 检测本地文件          │
│ 重新读取并解析 M3U8   │
│ 提取分辨率列表        │
└──────┬───────────────┘
       │
       ▼
┌──────────────────────┐
│ _create_task()       │
│ 将本地内容传递给      │
│ task 对象             │
└──────┬───────────────┘
       │
       ▼
┌──────────────────────┐
│ downloader_m3u8.py   │
│ 使用本地内容          │
│（跳过 fetch_m3u8）   │
│ 从远程 URL 下载分片   │
└──────────────────────┘
```

### 9.3 关键设计

- 本地 M3U8 内容存储在 `task.local_m3u8_content` 中
- 文件内的分片 URL 通常是绝对地址（`https://...`）
- 下载引擎直接使用这些远程 URL
- AES-128 密钥 URL 也从本地内容中解析

## 10. MP4 URL 检测

### 10.1 问题

部分 M3U8 URL 的路径中包含 `.mp4`：

```
https://cdn.example.com/hls/video.mp4/master.m3u8?token=xxx
```

简单正则 `\.mp4(\?\S*)?` 会将其误判为 MP4 链接，导致使用错误的下载方式。

### 10.2 解决方案

检查 URL 路径是否**以 `.mp4` 结尾**，而非仅仅包含：

```python
from urllib.parse import urlparse
parsed = urlparse(url)
is_mp4 = parsed.path.rstrip('/').lower().endswith('.mp4')
```

正确区分：
- `https://example.com/video.mp4` → MP4 ✓
- `https://example.com/video.mp4?token=xxx` → MP4 ✓
- `https://example.com/hls/video.mp4/master.m3u8` → M3U8 ✓
